# 3.2.1.0 — soft-delete search visibility

A soft-deleted memory could still be returned because Qdrant retained its previous
status and some recall paths did not enforce Neo4j's current state. Searches now
validate vector candidates against Neo4j before returning IDs or projecting
content. Working-memory recall honours its status argument, and fine graph recall
uses the same activated-state restriction as fast recall.

The change uses existing lifecycle fields. It adds no schema migration, embedding
rebuild, update endpoint, or global lock. Raw ID reads and unfiltered enumeration
retain their management semantics. Deletion followed by a new write remains
supported.

## Validation

- 87 relevant pytest cases passed; 3 existing Enterprise Neo4j integration cases
  were skipped because that optional backend was not configured.
- 34 checks passed against disposable, real Neo4j Community and Qdrant instances.
  Checks include precise deletion, stale payloads in both directions, recovery,
  delete-and-rewrite, Context projections, working memory, fine/fast recall,
  cube isolation, text-memory views, missing legacy fields and result ordering.
- The old runtime failed the real-backend delete-then-search assertion.
- All write tests used synthetic, isolated data. Production memory was not used
  as a test fixture.

The guarantee applies to searches started after the deletion transaction commits.
An already running search is not made globally linearizable. Filtering can return
fewer than top_k results; candidate overfetch is outside this patch.

## Local runtime image

The project maintenance version and image tag are 3.2.1.0. The vendored upstream
Python package version remains 2.0.34.

Use docker/Dockerfile.softdelete to inherit the previously deployed local runtime,
then copy only the two repaired source files. This preserves the existing runtime
dependencies and local overlays without committing unrelated work in progress.

The required base is llwwds/memos-local:2.0.34.0 with image ID:

    sha256:1adc6aad9ded19a33c860071433910deb580179fdb4968e1bd6a161c92a1ecf3

This is a local layered patch, not a fresh reconstruction of the earlier local
runtime from the repository alone. Keep the base image for rebuilding and rollback.
The Dockerfile-specific ignore file limits the build context to the patch inputs.

Build from the repository root, supplying the release commit to VCS_REF:

    docker build --network none \
      --build-arg VCS_REF=<release-commit> \
      --build-arg BASE_IMAGE_ID=sha256:1adc6aad9ded19a33c860071433910deb580179fdb4968e1bd6a161c92a1ecf3 \
      -f docker/Dockerfile.softdelete \
      -t llwwds/memos-local:3.2.1.0 .

The image labels expose the local version, source commit and inherited base ID.
The device-local Compose service should reference the new image and patch
Dockerfile. Recreate only the memos service; its existing database mounts and
dependency image versions remain in place.

Before upgrading, save the stopped database state and Compose configuration in
the existing application's restricted backup directory. A rollback changes the
memos image back to the retained base image and recreates that service; this patch
does not require a database rollback or migration.
